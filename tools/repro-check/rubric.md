# Rubric: is this reproduction package ready to post?

Every check reads the thing itself against the issue, never the write-up's shape. A terse report that shows the issue's behavior passes; a long confident one whose artifact shows something else fails.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env-recorded | The repro report's environment record (tool/package version, OS, install method or build, runtime) read against the issue's stated target and the repo-facts bug-report template asks. See evidence-guide "Environment". | Pass if the report names the version it tested plus the OS/platform, AND every factor the issue or thread says changes the failure (e.g. driver, build profile, shell, backend) is recorded. If the tested version differs from the issue's target, the report must say so in its own words. Fail if there is no environment record, if a failure-relevant factor is missing, or if the tested version silently differs from the one the issue targets (e.g. an old release against a bug confirmed on latest/main). | required |
| steps-rerunnable | The repro report's steps and commands, from starting state to the trigger, read against the issue's trigger. See evidence-guide "Steps". | Pass if a stranger with only public resources could run the steps and reach the trigger: the exact command(s) or code are shown and every input they need is either inline or public. Fail if the repro depends on private code, unshared config, or files not shown, or if the steps skip the action the issue says triggers the bug. | required |
| behavior-matches | The artifacts in the repro report (output excerpts, logs, error text, exit codes, screenshots described) read against the exact behavior the issue describes (error message, panic text, wrong value, exit code). Also compare the input used against the issue's input. See evidence-guide "Behavior shown". | Pass if the shown artifact displays the issue's specific behavior (same error/panic/wrong output, not merely "a failure"), produced by the issue's input or a faithful minimal version of it; OR the report is an honest cannot-reproduce whose artifact shows the attempt at the issue's trigger. Fail if there is no artifact, if the artifact shows a different symptom (a graceful syntax/validation error, a compile error, a still-running program when a crash was reported), or if the input was changed so the trigger no longer happens. | required |
| claims-backed | Every assertion in the claim comment and repro report ("confirmed", "deterministic", "root cause is X", "verified", "guaranteed") matched to a shown artifact. See evidence-guide "Honesty". | Pass if each claim of fact is backed by something shown in the package, and the stated outcome (reproduced / cannot reproduce / partial) matches what the artifacts show. Speculation labelled as a hypothesis is fine. Fail if the package asserts a reproduction, root cause, or scope (e.g. "also affects release X") that no shown artifact supports, or narrates a different artifact as the reported bug. | required |
| claim-specific | The candidate claim comment read against the issue. See evidence-guide "Comms". | Pass if the claim names something specific to this issue (the component, trigger, or observed behavior) and states a concrete next step that is investigation or testing, with no guaranteed fix or deadline. Fail if it is a bare +1 / "can I be assigned?", interchangeable boilerplate that would fit any issue, or promises a fix or a delivery date. | required |
| ai-disclosure | The repo-facts block's contribution policy (AI section) read against the claim comment and repro report. Course packages are AI-assisted work. See evidence-guide "Comms". | If the stated policy requires AI use to be disclosed in issues/comments (or "all AI usage in any form"), pass only if the comments disclose the AI assistance (tool and extent). If the policy requires human-written comments, pass only if the comments read as the contributor's own specific words (not generic AI boilerplate). If the policy only asks for disclosure in pull requests, is permissive, or there is no AI policy, pass. Fail if a required disclosure is missing. | required |
| template-asks | The repo-facts bug-report template asks, read against the repro report. | Pass if the report covers the template's asks (version, OS, command, expected vs actual) or the missing ones are irrelevant to this bug. | preferred |

## Verdict rule

accept if every required check passes. Preferred checks never change the verdict. unclear on a required check counts as fail, with one exception: an honest cannot-reproduce that shows its attempt at the issue's trigger and names what differed passes behavior-matches and claims-backed; it is not unclear.
